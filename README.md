# CloudBox — личное файлохранилище в Telegram

CloudBox — Telegram-бот на **Python 3.12+ / aiogram 3 / SQLAlchemy 2 / SQLite**, который
превращает личный чат с ботом в облачный каталог файлов.

Бот **не скачивает файлы на сервер**. Он сохраняет `file_id`, `file_unique_id` и
метаданные в SQLite, а при необходимости отправляет файл обратно по `file_id`.
Сами файлы остаются в инфраструктуре Telegram.

## Возможности

- доступ только для пользователей из белого списка;
- администратор из `.env`, добавление и блокировка пользователей;
- приём документов, фото, видео, аудио, голосовых, видеокружков и анимаций;
- защита от дубликатов по `file_unique_id` в рамках пользователя;
- каталог с пагинацией;
- отправка файла обратно в чат;
- переименование и удаление записей;
- поиск по названию (корректно работает с кириллицей);
- избранное (в том числе для файлов из общих папок);
- вложенные папки, создание, переименование и удаление;
- перемещение файлов между папками;
- общие папки с доступом на чтение и опциональной загрузкой;
- личная и общая (для администратора) статистика;
- подтверждение загрузки, в том числе одно сообщение на альбом;
- обработка ошибок Telegram API и ограничение размера файла.

## Как это работает

1. Пользователь отправляет файл боту.
2. Бот извлекает `file_id`, `file_unique_id`, имя, размер, MIME-тип и дату.
3. Запись сохраняется в SQLite и привязывается к владельцу и папке.
4. При повторной отправке бот вызывает `send_document` / `send_photo` / … с
   сохранённым `file_id`.

`file_unique_id` используется **только** для защиты от дубликатов. Для отправки
файла он не подходит — Telegram требует `file_id`.

## Требования

- Linux (проверено на Python 3.14, поддерживается 3.12+);
- `python3`, `python3-venv`, `pip`;
- токен бота от [@BotFather](https://t.me/BotFather);
- ваш Telegram ID (например, узнать у [@userinfobot](https://t.me/userinfobot)).

## Установка на Linux

```bash
# 1. Каталог проекта
cd /opt
sudo mkdir -p cloudbox
sudo chown "$USER":"$USER" cloudbox
cd cloudbox

# 2. Файлы проекта уже должны быть здесь.
#    Создаём виртуальное окружение
python3 -m venv .venv
source .venv/bin/activate

# 3. Зависимости
pip install --upgrade pip
pip install -r requirements.txt

# 4. Конфигурация
cp .env.example .env
nano .env
```

Минимальный `.env`:

```dotenv
BOT_TOKEN=123456789:YOUR_TOKEN_HERE
ADMIN_ID=123456789
DATABASE_URL=sqlite+aiosqlite:///data/cloudbox.db
```

Полный набор параметров:

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `BOT_TOKEN` | да | — | токен от BotFather |
| `ADMIN_ID` | да | — | Telegram ID администратора |
| `ALLOWED_IDS` | нет | пусто | стартовый белый список через запятую |
| `DATABASE_URL` | нет | `sqlite+aiosqlite:///data/cloudbox.db` | URL БД; относительный путь считается от корня проекта |
| `PAGE_SIZE` | нет | `8` | элементов на страницу (3–20) |
| `MAX_FILE_SIZE_MB` | нет | `2000` | локальный предохранитель по размеру (1–4096 МБ) |
| `LOG_LEVEL` | нет | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` |
| `TIMEZONE` | нет | `UTC` | часовой пояс для дат, например `Europe/Moscow` |

Запуск:

```bash
source .venv/bin/activate
python -m cloudbox
```

При первом запуске создаются таблицы и администратор из `ADMIN_ID`.
Пользователи из `ALLOWED_IDS` добавляются один раз, если их ещё нет в БД
(повторный запуск не разблокирует вручную заблокированных).

## Создание бота в BotFather

1. Откройте [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Укажите отображаемое имя, например `CloudBox`.
3. Укажите username, оканчивающийся на `bot`, например `my_cloudbox_bot`.
4. Скопируйте токен вида `123456789:AA...` в `BOT_TOKEN`.
5. Узнайте свой Telegram ID (например, через [@userinfobot](https://t.me/userinfobot))
   и укажите его в `ADMIN_ID`.
6. По желанию задайте команды через `/setcommands`:

```text
start - Главное меню
help - Помощь
cancel - Отменить текущий ввод
```

Токен — секрет. Не публикуйте его, не коммитьте `.env` и не пересылайте бота
третьим лицам. Смена токена делает все сохранённые `file_id` недействительными.

## Первый запуск и пользователи

1. Запустите бота и отправьте ему `/start`.
2. Убедитесь, что вы вошли как администратор.
3. Добавьте пользователей:
   - через `/adduser 123456789`;
   - или «⚙️ Настройки» → «👑 Админ-панель» → «👥 Пользователи» → «➕ Добавить».
4. Пользователь должен отправить боту `/start`; после этого обновятся его имя и
   username.

Заблокировать пользователя: `/deluser 123456789` или кнопка «🚫 Заблокировать»
в админ-панели. Записи файлов при блокировке сохраняются. Разблокировка
возвращает доступ.

## Использование

### Загрузка

- Просто отправьте боту документ, фото, видео, аудио, голосовое, видеокружок
  или анимацию.
- По умолчанию файл попадёт в корень.
- Чтобы загрузить в папку: «📁 Мои файлы» → откройте папку → «📤 Загрузить сюда»
  (или «📤 Загрузить» в меню → выберите папку). Отправляйте файлы, затем
  нажмите «✅ Готово».
- Если файл уже есть у вас в каталоге, бот покажет существующую запись и
  предложит переместить её.

### Каталог

- «📁 Мои файлы» — папки и файлы в корне.
- Откройте папку, чтобы увидеть вложенные папки и файлы.
- Пагинация — кнопки `⬅️` / `➡️`.
- Карточка файла: отправка, избранное, переименование, перемещение, удаление.

### Папки

- «📂 Мои папки» → «➕ Новая папка».
- Внутри папки: «➕ Подпапка», «✏️ Переименовать», «🗑 Удалить».
- При удалении папки бот предлагает:
  - «📤 Файлы наверх» — записи сохраняются и переезжают в родительскую папку
    (или в корень);
  - «🗑 Удалить всё» — удаляются папки и записи файлов внутри.

### Общие папки

1. Владелец открывает папку → «👥 Доступ» → «➕ Добавить пользователя».
2. Вводит числовой Telegram ID пользователя, который уже добавлен в белый список.
3. По умолчанию выдаётся доступ на чтение: получатель видит папку и может
   отправлять файлы себе.
4. Кнопка `👁` / `✏️` переключает право загрузки в папку.
5. `❌` отзывает доступ. Получатель может сам покинуть папку кнопкой
   «🚪 Покинуть папку».

Файлы, загруженные в общую папку, принадлежат тому, кто их загрузил. Владелец
папки может удалить чужую запись из своей папки (с подтверждением), но не может
переименовать её. Удаление записи не удаляет сам файл из Telegram.

### Поиск и избранное

- «🔍 Поиск» — введите часть названия. Ищет по своим файлам и по доступным
  общим папкам.
- «⭐ Избранное» — файлы, отмеченные звёздочкой в карточке.

### Администратор

- `/users` — список пользователей с количеством файлов.
- `/adduser <tg_id>` — добавить или разблокировать.
- `/deluser <tg_id>` — заблокировать.
- `/stats` — личная и общая статистика.
- «⚙️ Настройки» → «👑 Админ-панель» — те же действия в интерфейсе.

Обычным пользователям команды администратора недоступны.

## Ограничения и важные детали

- **Размер файла.** CloudBox не скачивает файлы и не загружает их заново, поэтому
  ограничение Bot API в 50 МБ для multipart-загрузки и лимит `getFile` в 20 МБ
  здесь не применяются: отправка по `file_id` не имеет ограничения размера по
  документации Telegram. `MAX_FILE_SIZE_MB` — локальный предохранитель
  (по умолчанию 2000 МБ), его можно изменить в `.env`. Telegram всё равно
  ограничивает размер исходной загрузки в чат (обычно 2 ГБ, 4 ГБ для Premium).
  Для файлов больше лимита бот покажет понятную ошибку.
- **`file_id` привязан к боту.** Если сменить `BOT_TOKEN` или пересоздать бота,
  сохранённые записи перестанут отправляться. Не теряйте токен; делайте резервные
  копии `.env` и БД.
- **Удаление записи не удаляет файл.** В SQLite хранятся только метаданные.
  После удаления записи файл остаётся в Telegram, но бот теряет возможность
  отправить его повторно.
- **Исходное сообщение лучше не удалять.** `file_id` — это ссылка на файл в
  инфраструктуре Telegram. Если удалить исходное сообщение с файлом (или чат),
  Telegram может сделать ссылку недействительной, и бот не сможет отправить
  файл повторно. CloudBox не создаёт собственную копию файла.
- **SQLite и один процесс.** Не запускайте несколько экземпляров бота на одной
  базе. Используется WAL и `busy_timeout`, но это не заменяет сервер БД.
- **FSM в памяти.** Незавершённые вводы (переименование, создание папки) теряются
  при перезапуске. Данные файлов при этом не страдают.
- **Часовой пояс.** В БД время хранится в UTC, отображается в `TIMEZONE`.
- **Приватность.** Файлы доступны только владельцу и получателям доступа к
  папке. Все операции с файлами проходят проверку прав в сервисах.
- **WAL-файлы.** Для консистентной резервной копии остановите бота и скопируйте
  `cloudbox.db`, `cloudbox.db-wal`, `cloudbox.db-shm` или используйте
  `sqlite3 data/cloudbox.db ".backup 'backup.db'"`.

## Публикация на GitHub

`.gitignore` уже исключает `.env`, базу данных, бэкапы, виртуальное окружение,
логи, кэши, ключи и локальные файлы. Перед первым push проверьте, что в индекс
попали только безопасные файлы:

```bash
cd /opt/cloudbox
git init
git add -A
git status --short

# Ничего не должно вывести эти команды:
git ls-files --cached | grep -E '(^|/)\.env($|\.)' | grep -vE '\.env\.example$' || true
git ls-files --cached | grep -E '\.(db|sqlite3?)(-|$)' || true
```

В индексе должны быть исходники, `README.md`, `requirements.txt`,
`.env.example`, `.gitignore` и `data/.gitkeep`. Файла `.env` там быть не должно.

```bash
git commit -m "Initial CloudBox bot"
git branch -M main
git remote add origin git@github.com:USERNAME/cloudbox.git
git push -u origin main
```

Проверить конкретный файл:

```bash
git check-ignore -v .env
```

Если `.env` или база когда-либо уже попадали в git-историю, `.gitignore` их не
удалит из старых коммитов. В этом случае:

1. отзовите токен у `@BotFather` (`/revoke`) и выпустите новый;
2. удалите секрет из истории (`git filter-repo` или BFG Repo-Cleaner);
3. при необходимости смените пароли и ключи, которые были в репозитории.

Никогда не публикуйте `.env`, `data/cloudbox.db`, бэкапы и файлы ключей.

## systemd

Создайте отдельного пользователя (рекомендуется) и unit:

```bash
sudo useradd --system --home /opt/cloudbox --shell /usr/sbin/nologin cloudbox
sudo chown -R cloudbox:cloudbox /opt/cloudbox
sudo nano /etc/systemd/system/cloudbox.service
```

```ini
[Unit]
Description=CloudBox Telegram bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=cloudbox
Group=cloudbox
WorkingDirectory=/opt/cloudbox
Environment=PYTHONUNBUFFERED=1
ExecStart=/opt/cloudbox/.venv/bin/python -m cloudbox
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now cloudbox
sudo systemctl status cloudbox
sudo journalctl -u cloudbox -f
```

Права на `.env`: `chmod 600 .env`, владелец — `cloudbox`.

## Резервное копирование

```bash
sudo systemctl stop cloudbox
sqlite3 /opt/cloudbox/data/cloudbox.db ".backup '/opt/cloudbox/backup-$(date +%F).db'"
sudo systemctl start cloudbox
```

Храните копию `.env` отдельно: без прежнего `BOT_TOKEN` старые `file_id`
не будут работать.

## Возможные проблемы

**«Доступ к CloudBox закрыт».** Пользователя нет в белом списке или он
заблокирован. Админ добавляет его по Telegram ID: `/adduser <id>`.

**«Telegram не принял file_id».** Сменился `BOT_TOKEN` или запись повреждена.
Вернуть старую отправку нельзя — файл нужно загрузить заново.

**«Файл слишком большой».** Это локальный предохранитель `MAX_FILE_SIZE_MB`.
Увеличьте его в `.env`, если уверены, что Telegram примет файл.

**Ошибка `database is locked`.** Убедитесь, что запущен только один экземпляр
бота и что каталог `data/` доступен на запись.
